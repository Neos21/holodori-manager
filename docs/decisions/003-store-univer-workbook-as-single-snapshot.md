# ADR-003 : Univer ワークブックを単一スナップショットとして保存する

- 状態 : 採用


## Context (背景・課題)

[Univer Sheets](https://docs.univer.ai/ja-JP/guides/sheets) の `IWorkbookData` はシートデータの他に、シート順、ワークブック共通スタイル、条件付き書式などのプラグインデータを持つ。シートごとに DB レコードを分ける場合、保存時と読込時にワークブックを分解・再構築し、各データの整合性を維持する必要がある。

D1 の1行あたりの上限は 2,000,000 バイトである。現在想定する約 26KB のテキストデータは `IWorkbookData` 形式の JSON 文字列にしても 162KB (インデント整形されると 859KB)。データ容量にはまだ余裕があり、予想されるデータ増分もさほどないため、1シート単位での分割はせずワークブック全体で保持することとする。


## Decision (意思決定)

- `workbooks` テーブルの1レコードに `IWorkbookData` 全体を JSON 文字列として保存する
- 現在の画面は `workbooks.id = 1` の単一ワークブックだけを扱う
- API はワークブック全体を取得・置換し、セル単位やシート単位の部分更新を行わない
- `sheets` テーブルは作成しない


## Consequences (結果・影響)

- Univer Sheets が生成したスナップショットを分解せず保存でき、条件付き書式を含むプラグインデータを欠落させにくい
- ワークブック全体を1回のクエリで読み書きでき、複数テーブル間の整合性制御が不要になる
- 保存のたびにワークブック全体を通信・更新する
- データ量が D1 の1行上限に近づいた場合は、シート数や UTF-8 バイト数を計測して保存方式を再検討する必要がある


## Rejected Alternatives (却下した選択肢)

- `workbooks` と `sheets` に分割し、シートごとの JSON を保存する
    - 現在のデータ規模では D1 の上限まで余裕があり、`styles`、`sheetOrder`、`resources` と各シートを分解・再構築する複雑さが先行するため採用しない
- セル単位で部分更新する
    - 条件付き書式など他セルに作用する機能を含むスナップショットの整合性を、アプリケーション側で再現する必要があるため採用しない
