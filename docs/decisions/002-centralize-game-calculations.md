# ADR-002 : ゲーム計算を共有 Service に一元化する

- 状態 : 採用


## Context (背景・課題)

ホロワークアチーブメント進捗とボードノード最終レートは、クライアント表示とサーバ側の候補・集計処理の両方で必要になる。SQL、クライアント、サーバに同じ式を個別実装すると、閾値や計算式の変更時に差異が生じる。


## Decision (意思決定)

- ゲーム固有の計算を `shared/services/` に置く
- SQL、クライアント、サーバに同じ計算式を重複させない
- 表示用の数値整形は、ゲーム上の計算規則と分離する


## Consequences (結果・影響)

- 画面表示、一覧集計、候補選定が同じ計算規則を利用できる
- 閾値や計算式の修正箇所を限定できる
- SQL だけで集計を完結させる場合より TypeScript 側の集約処理は増えるが、計算規則と型を共有できる


## Rejected Alternatives (却下した選択肢)

- SQL の `CASE` や集計式で計算する
    - クライアント表示と同じ規則を別実装することになるため採用しない
- 各画面・Service に小さな計算関数を置く
    - 同じゲーム規則が複数箇所に分散するため採用しない
