# Domain

本プロジェクトが扱うゲーム用語、データ上の不変条件、計算規則を示す。DDL の正本は [create-tables.sql](../migrations/create-tables.sql) とする。


## ゲーム用語

| ゲーム内正式名称 | 説明                                                                 |
|------------------|----------------------------------------------------------------------|
| ホロメン         | キャラクター。1人が複数のメンバーカードを持つ                        |
| メンバーカード   | レア度ごとに存在し、現状は星3・4・5を扱う。イベントで種類が増加する  |
| ホロワーク       | 一定時間の放置で報酬アイテムを得るミニゲーム                         |
| ホロメンボード   | マスを解放して報酬アップなどの効果を得る育成要素                     |
| コネクトマス     | 隣接マスの効果を増幅する機能                                         |
| スコア           | ホロメン1人または5人ユニット全体の強さ指標。現時点では直接管理しない |


## ホロメン

- `holomems.is_active` で卒業等による無効化を表し、物理削除しない
- 新規追加時は、星3・4・5のカードを `is_owned = 0` (未所有) で作成し、ホロワーク達成状況の初期レコードも作成する
- `sort_order` はアプリ上 1 以上を入力するが、DB の `DEFAULT` は 0 とする
- `sort_order` に `UNIQUE` 制約は設けず、同値の場合は `id ASC` で順序を確定する (DB に `UNIQUE` 制約を設けてしまうと表示順を変更したい場合の画面操作が煩雑になってしまうため)
- DB 直接操作で `sort_order = 0` が存在しても除外せず、その値を含めて昇順表示する


## カード

- レア度は3・4・5のいずれかとする
- 一覧は `holomems.sort_order ASC`、`holomems.id ASC`、`rarity DESC`、`cards.id ASC` の順とする
- 同じホロメン・レア度では、先に登録された通常版、後に登録されたイベント版の順になることを想定する


## ホロメンボード

| カテゴリ | 用途                 | 管理方針                                     |
|----------|----------------------|----------------------------------------------|
| `yellow` | ホロワーク報酬アップ | 数値管理し、候補選定に利用する               |
| `green`  | ミニゲーム報酬アップ | 黄マスと同じ構造で数値管理する               |
| `red`    | 音ゲー・リーダー用途 | 詳細管理せず、ホロメンの自由記入欄で運用する |
| `blue`   | 音ゲー・メンバー用途 | 詳細管理せず、ホロメンの自由記入欄で運用する |

表示上のカテゴリ順は `yellow`、`green`、`red`、`blue` とする。カテゴリ内では `holomems.sort_order ASC`、`holomems.id ASC`、`board_nodes.id ASC` の順に表示する。

マスの最終レートは、計算済みの列を DB に持たず次の式で算出する。

```text
最終レート = amount × (1 + (connect_rate ?? 0) / 100)
```

ホロワークの報酬アップ量には、`category = yellow` かつ `is_unlocked = 1` のマスだけを使用する。同じ対象アイテムの最終レートをすべて加算し、計算途中では丸めず、表示時だけ小数第2位まで固定表示する。


## ホロワーク

- 枠は DB レコードとして追加・物理削除できるが、編集機能は持たない
- 1枠につき1人以上5人以下で開始する
- `active_holowork_members` の登録有無で活動中を表す
- 同じホロメンは複数枠で同時に活動できない
- 活動中メンバーがいる枠は削除できない
- 完了では全メンバーの完了回数を1増やしてから解放する
- 中断では完了回数を増やさずに解放する

ホロワーク管理機能の画面・候補・操作仕様は [features/holoworks.md](./features/holoworks.md) を参照のこと。


## ホロワークアチーブメント

全ホロメン共通の完了回数閾値は次のとおり。定数 `holoworkAchievements` にて定義してある。

```text
1, 5, 10, 30, 50, 100, 200, 300, 400
```

- `current_count` より大きい最小の閾値を `next_threshold` とする
- `remaining_count = next_threshold - current_count` とする
- 400回以上では全達成として、`next_threshold` と `remaining_count` を `null` にする
- 活動中か否かは `active_holowork_members` から導出し、達成状況テーブルには重複して保持しない


## High & Low

High & Low は、ファイブカードドロー形式のポーカーで得たコインを、任意のダブルアップチャンスで増やせるミニゲームである。計算ページの入力・推奨・収支管理仕様は [features/high-and-low-calculator.md](./features/high-and-low-calculator.md) を参照のこと。

### ポーカー

- 1プレイの開始時に50コインをベットする
- 山札は通常のトランプカード52枚とジョーカー1枚の計53枚で構成する
- ランクは 2 を最小、A を K より大きい最大として扱う
- 最初に配られた5枚から0枚以上5枚以下を保持し、保持しなかったカードを残りの山札から交換する
- ジョーカーは任意の通常トランプカードとして扱い、成立する中で最も強い役を採用する

交換後の5枚で成立する役と配当は次のとおり。獲得コインは50コインに倍率を掛けて算出する。

| 役                   | 成立条件                                             | 倍率 | 獲得コイン |
|----------------------|------------------------------------------------------|------|------------|
| 不成立               | 配当のある役が成立しない                             |   ×0 |          0 |
| ワンペア             | 同じランク2枚の組み合わせが1つ                       |   ×0 |          0 |
| ツーペア             | 同じランク2枚の組み合わせが2つ                       |   ×4 |        200 |
| スリーカード         | 同じランクが3枚                                      |   ×4 |        200 |
| ストレート           | 異なる5ランクが連続する                              |   ×8 |        400 |
| フラッシュ           | 5枚のスートが同じ                                    |  ×14 |        700 |
| フルハウス           | ワンペアとスリーカードが同時に成立する               |  ×16 |        800 |
| フォーカード         | 同じランクが4枚                                      |  ×30 |      1,500 |
| ストレートフラッシュ | ストレートとフラッシュが同時に成立する               |  ×60 |      3,000 |
| ファイブカード       | 同じランクの通常トランプカード4枚とジョーカーが揃う  | ×140 |      7,000 |
| ロイヤルフラッシュ   | 同じスートの 10・J・Q・K・A が揃う                   | ×200 |     10,000 |

ストレートでは 10・J・Q・K・A を連続として扱う。A は最大ランクとしてのみ扱うため、A・2・3・4・5 や J・Q・K・A・2 では成立しない。配当のある役が成立した場合は、獲得予定のコインを確定するか、ダブルアップチャンスに使用するか選択できる。

### ダブルアップチャンス

- ポーカーとは独立した、ジョーカーを含まない52枚の山札を使う
- 提示カードに対して、次にめくられるカードのランクが「たかい」か「ひくい」かを予測する
- A を最大、2 を最小として比較し、スートは大小判定に影響しない
- 進行中に登場したトランプカードは残りの山札から除外する
- 予測が成功すると見込みコインが2倍になり、利確するか次のダブルアップに挑戦するか否かを選択できる
- 予測に失敗すると、そのプレイの獲得コインは0枚になる

提示カードと同じランクがめくられた場合は成功・失敗のどちらにもならない。めくられた同ランクのカードを新しい提示カードとして、改めて「たかい」か「ひくい」かを予測する。

### 獲得上限

- 1プレイでは、見込みコインが10,000枚を超えた時点でダブルアップを終了し、そのコインを強制的に確定する
    - 200枚から開始した場合は、12,800枚になった時点で確定する
- 本日の確定済み獲得コインが20,000枚を超えると、新しいポーカーを開始できない
    - 20,000枚ちょうどの時点では、もう1プレイ開始できる
- 1日あたりのプレイ回数には上限がない

日次上限は「20,000枚を超えた時点」で新規プレイを停止するため、1日の最終獲得額が20,000枚を超える場合がある。例えば12,800枚、6,400枚、12,800枚の順に確定すると、合計32,000枚を獲得できる。


## メモ

- 自由メモは `memos` テーブルで複数レコードを管理する
- `memos.id = 1` は必ず存在するデフォルトメモとし、物理削除しない
- ID の欠番は再採番しない

画面上の操作仕様は [features/memos.md](./features/memos.md) を参照のこと。
